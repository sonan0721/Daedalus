## 현재 토론

사용자는 예측 가능한 결정을 미루지 않기를 원한다. 초기 TS strict 권고와 실제 사례 검토 후, 플러그인형 PC 모드·C# 작성 경험·V8/Chromium 제외·오토파일럿 요구를 반영해 C#을 선택했다. 최종 결정은 [ADR-0003](../05-decisions/0003-csharp-and-native-gameplay.md)이다. Rust 게임플레이는 빌드 시 반영하고 C#이 hot-reload를 담당한다. 다음 조사는 언어 재선정이 아니라 host·ABI·SDK·수명·배포의 구체화다.

실시간 답변이 도착하면 해당 질문의 답과 영향받는 문서를 갱신한다. 답변이 없다는 이유로 옵션의 첫 항목을 채택하지 않는다.

## 변경·충돌 기록

- 원안에서 UI·서버가 마지막 단계였지만 A-004·A-007에 따라 초기 공통 설계로 이동.
- 처음 설명했던 별도 검증 프로젝트 구상은 A-012로 현재 범위에서 제외. 현재 산출물은 엔진의 구조·품질·검증 명세이다.
- “전체 플랫폼”은 사용자 목표이며 현재 지원 인증이 아니다. 플랫폼별 달성 증거는 이후 별도로 기록.
- 모든 플랫폼의 다운로드 모드를 원했던 중간 답변은 A-028·029가 대체한다. 웹·모바일 엔진 자체의 목표를 취소한 것으로 해석하지 않는다.
- 초기 TS 권고는 A-030·032의 C# 선택으로 대체했다. 과거 비교·출발 제안은 조사 이력으로 보존한다.
- A-040에 따라 과거 “현재 sample game 불필요”를 영구 금지로 해석하지 않는다. 엔진 repository는 그대로 엔진 전용이며 D1 완료 후 별도 3D game, 이어 별도 2D game을 인수한다. 조정자의 checkpoint 종료 보고는 전체 목표 완료 근거가 아니다.

## 다음 대화 운영

설계 탐색에서는 서로 관련된 질문을 묶고, 답에 따라 달라지는 소유권·시뮬레이션·렌더·배포 선택을 설명한다. 현재 구현 중에는 이미 결정한 요구를 다시 묻지 않고 문서·실행 근거를 먼저 확인한다. 사용자가 현재 명세 내용을 질문하면 기존 계획을 답하며 역질문으로 대신하지 않는다. 전체 질문 풀은 [질문지](questionnaire.md)에 둔다.
