# E04: C# host·실제 Rust world·모듈 교체 검증

날짜: 2026-10-15 · 구현 Luna xhigh · 조정자 독립 실행 확인

## 실제 연결

`daedalus-bridge`는 Rust `Engine`을 소유하는 cdylib다. C# host는 ABI1을 확인하고 opaque u64 token·bounded UTF-8 JSON·Rust-owned response release로 호출한다. managed ECS를 따로 만들지 않는다. 엔티티 session/command ID는 decimal string이며 tick/revision은 초기 core의 numeric JSON 계약을 유지한다.

SDK와 shared interface는 default load context에서 공유하고, fixture module은 별도 collectible AssemblyLoadContext에서 로드한다. module local state를 캡처·복원하고 callback 명령을 staging한 뒤 실제 Rust StepReport의 Applied를 확인하고 generation을 바꾼다. 실패 candidate의 명령과 cleanup 등록은 되돌리고 이전 module을 유지한다.

## 리뷰에서 보완한 문제

- Rust snake_case와 managed serializer의 camelCase가 달랐다. protocol naming과 실제 응답 필드 조회를 맞췄다.
- registry instance·buffer 개수·retained bytes와 한 요청의 aggregate 작업/응답 예산을 제한했다. 출력 credit을 확보할 수 없으면 world mutation 전에 거부한다.
- 기존 pending command가 있는 queue에서 교체 명령 일부만 적용될 수 있어 initial atomic batch는 queue가 비어 있어야 한다. bridge가 만드는 engine에는 별도 Rust gameplay system이 등록되지 않는다. 일반 transaction 또는 모든 게임플레이와의 atomic 교체가 완성됐다는 뜻은 아니다.
- SafeHandle 수명을 native exchange 동안 유지하고 실제 token은 명시적 u64로 전달한다. 현재 managed host는64bit만 지원한다.
- callback 내부는 staged read-your-writes를 지원한다. 실패한 callback에서 새 cleanup을 회수하며 per-generation 등록 수·회수 대기 context 수를 제한한다. 회수가 막히면 새 교체를 먼저 거부해 기존 generation을 유지한다.

## 조정자 실행

macOS-arm64·Rust1.94.0·SDK10.0.402·CoreCLR10.0.13에서 다음을 실행했다. 로컬 PATH의 이전 dotnet 대신 설치 확인한 SDK 경로로 실행했고, 아래 명령은 해당 SDK가 PATH에 있는 환경의 표기다.

```sh
cargo test -p daedalus-bridge --locked
cargo build -p daedalus-bridge --locked
dotnet build managed/Daedalus.slnx --configuration Release --no-restore
DAEDALUS_NATIVE_PATH="$PWD/target/debug/libdaedalus_bridge.dylib" \
  dotnet run --no-build --project managed/Daedalus.ManagedHost --configuration Release -- --self-test
DAEDALUS_NATIVE_PATH="$PWD/target/debug/libdaedalus_bridge.dylib" \
  dotnet run --no-build --project managed/Daedalus.ManagedIntegrationTests --configuration Release
```

Rust bridge6건 통과, .NET build 경고0/오류0, self-test의 실제 Rust entity `x=2`·revision1 확인. integration executable의2개 scenario가 통과했다. scenario 안에서 native round-trip, V1→V2 state/ID/위치 보존, 실패 migration의 명령 미반영·이전 로직 유지, 실패 tick cleanup, 반복 context 회수를 확인했다. assertion 수를 개별 test 수로 부풀리지 않는다.

Luna는 host의 명시적 `--reload` command도 실행했다. 조정자의 직접 결과와 작성자 실행 결과를 구분한다. Linux managed workflow를 추가했지만 이 기록 작성 시 해당 새 workflow의 원격 결과는 아직 없다.

## 현재 제한

현재 공식 SDK는 transform 경로에 한정된다. 일반 ECS schema/query·physics/UI/content API·C# system scheduler·권한/이벤트 체계·자동 source build/watch·runtime 동봉·웹 C# 실행은 후속이다. whole-module 명시적 교체이며 MetadataUpdater delta edit가 아니다. reload latency와 144fps를 측정하지 않았다.

native registry는 synchronous mutex로 exchange·tick·종료를 직렬화한다. frame callback에서 사용하는 고성능 per-component 경로가 아니다. initial host/control 경계의 정확성을 확인한 결과다. trusted in-process module은 임의 .NET/native/I/O를 실행할 수 있어 ALC를 sandbox로 표시하지 않는다. 상세 API와 실제 CLI는 [managed 안내](../../managed/README.md)에 둔다.
