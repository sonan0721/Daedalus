# 다이달로스 워터폴 마스터플랜

상태: 전체 목표 진행 중·D1 엔진 제품 인수 미통과 · 2026-10-16

## 상위 납품 순서와 현재 실패 조건

상위 워터폴은 **D1: AI-driven 엔진 제품 인수 → D2: 별도 Minecraft급 3D 게임 인수 → D3: 별도 Terraria급 2D 게임 인수**다. [제품 인수 계약](product-delivery-and-acceptance.md)의 P01~P16을 기준으로 진행하며, 기존 W0~W8은 D1 내부의 설계·구현·품질 gate다. W단계의 작은 fixture 통과로 D1을 종료하지 않는다. D2/D3에서도 공통 엔진 결함은 해당 gate를 재개방한다.

`bbccc56`은 기반 구현이며 W1/W2를 포함한 미통과 항목이 남아 있다. 현재 project lifecycle·일반 asset 제작·완성 UI·animation·30명 network·save·game export 등은 미완료다. 다음 작업은 [준비도 감사](../06-worklog/2026-10-16-product-readiness-audit.md)를 따라 미통과 계약과 선행 구현을 채운다. 전체 목표는 세 제품의 인수가 모두 끝날 때까지 열어둔다.

## 운영 원칙

품질 우선 요구에 따라 필수 산출물과 인수 기준을 충족한 뒤 다음 구현 단계로 진행한다. 조사·명세는 새 근거에 따라 수정할 수 있다. 지나간 단계의 결정을 고치지 못하는 경직된 워터폴로 해석하지 않고, 변경 이유·영향·새 검증을 기록한다.

사용자가 설계 기반 엔진 구축을 시작하도록 명시했다. [ADR-0004](../05-decisions/0004-start-engine-implementation.md)에 따라 모듈별 계약을 보완하며 Luna xhigh가 구현한다. W1/W2 전체가 통과됐다고 표시하지 않는다. 구현·실험·품질 검증의 실제 진행은 [구현 체크리스트](implementation-checklist.md)에서 추적하며 기술 가설을 문서만으로 증명한 것처럼 표시하지 않는다.

## 게이트 보고서와 변경

각 게이트는 `commit / 요구 / 환경 / 명령 / 결과 / artifact / 미통과 / 면제 사유와 결정자 / 후속`을 가진다. 필수 기준 면제는 사용자의 명시적 범위 결정 없이는 통과로 처리하지 않는다. 새 요구로 이전 단계가 무효화되면 영향 문서·ADR·시험을 재개방한다.

## D2·D3 실게임 검증

D1 통과 뒤 별도 game project에서 engine 공개 SDK·scene·asset·UI·network·physics/audio를 소비해 3D 게임을 제작한다. 메뉴부터 실제 플레이·30명 server·지속 월드·배포까지 품질과 제작 경로를 인수한 뒤 2D 게임에 착수한다. 두 차원 모두 기능이 연결된 실제 게임이어야 하며 단일 block/tile 시연으로 대체하지 않는다.

개발 반복 비용 개선도 [별도 파이프라인](development-iteration-pipeline.md)으로 추적한다. 코드/에셋/도구를 재사용하는 것은 허용하되 기능·품질·인수 gate를 삭제하는 최적화는 허용하지 않는다.
