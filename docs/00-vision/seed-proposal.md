# 출발 제안과 변경 추적

상태: 대화 원안의 구조화된 요약. 원문 전체의 전사본은 아님 · 2026-10-15

## 처음 제안이 전달한 의도

- GUI 에디터 중심 대신 Rust + TypeScript + DCC + CLI/MCP를 통한 AI 중심 제작.
- 작업 기반 병렬 처리, 시뮬레이션과 렌더 분리, 로딩 중에도 반응하는 UI.
- wgpu 기반 PBR, 그림자, Bloom·SSAO·TAA, GPU 파티클, 네이티브 UI.
- 3D 복셀 생성·메시·조명 스트리밍과 2D 파괴 지형·유체·빛 시뮬레이션.
- TS 로직 핫리로드 중 엔티티 상태 보존.
- GPU 오프스크린 렌더와 이미지 캡처를 통한 AI 피드백.
- 전용 서버와 클라이언트 동기화.

## 제안된 부품

Rust, Bevy ECS, wgpu, Rayon, Crossbeam, Jolt, rquickjs 또는 Deno Core, oxc, notify, Lightyear, bevy_hanabi, Taffy, ozz-animation, Spine, WebP 인코더가 후보로 언급되었다. **후보 목록은 최종 채택 목록이 아니다.** 독립 엔진에서의 결합 비용과 웹 지원을 따로 확인한다.

## 원래 6단계와 수정 방향

| 출발 단계 | 유지할 목적 | 다이달로스에서 보완할 점 |
| --- | --- | --- |
| Core / Job System | 안전한 데이터 소유권과 작업 병렬성 | 엔티티 수만이 아니라 실제 작업량·p99 지연·메모리·과부하로 검증 |
| TypeScript | 빠른 반복과 상태 보존 | 네이티브·브라우저 실행 계약, 변경 세대, 롤백·마이그레이션 추가 |
| Renderer / Headless | 실제 GPU 이미지 피드백 | 최소 시각 검증을 조기에, 고급 렌더는 확장 단계로 분리 |
| Minecraft형 기능 | 복셀 저장·생성·메시·스트리밍 | 엔진 서브시스템으로 명세. 샘플 게임은 현재 만들지 않음 |
| Terraria형 기능 | 타일·유체·조명·파괴 시뮬레이션 | 3D와 동등한 엔진 목표. 질량 보존·경계 교환·예산 추가 |
| UI / VFX / Server | 완성도와 네트워크 | UI 반응성과 서버 권한 설계를 초기 공통 코어에 이동 |

## 검증 대상으로 보존할 수치

원안의 144Hz, UI 60fps, 트랜스파일 5ms, 핫리로드 50ms, 10만 엔티티, 1초 내 애니메이션 캡처는 사용자의 최종 성능 계약으로 확정되지 않았다. 기준 기기, 해상도, 씬, 스크립트 크기, 워밍업, 인코딩 조건을 정한 뒤 시험 가능한 목표로 재작성한다. [주장 검증](../02-research/claim-audit.md)에 판정과 대체 표현을 둔다.

## 후속 대화로 확정된 변경

프로젝트 이름은 Daedalus로 변경한다. 독립 엔진을 지향하고, macOS·웹을 우선하며 다중 플랫폼으로 확장한다. 전용 서버는 초기 설계 요구이다. 이 저장소에는 엔진과 엔진 문서를 커밋하며 샘플 게임을 시작하지 않는다. 게임 품질 참조는 [헌장](project-charter.md)에 기록한다.
