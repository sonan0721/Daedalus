# R01: 기획·조사·설계 첫 라운드

날짜: 2026-10-15 · 단계: 엔진 구현 전

## 범위

빈 Git 저장소에서 다이달로스 엔진의 요구·질문·1차 자료·주장 검증·아키텍처·목표·게이트·기여 기반을 정리했다. 사용자 요청에 따라 샘플 게임과 엔진 런타임은 시작하지 않았다. 라이브러리 통합·GPU·144fps·30명 서버 성능을 검증했다고 주장하지 않는다.

## 사용자 답변의 반영

독립 엔진, macOS·웹 우선, 전 플랫폼 지향, 픽셀/HD 2D와 복셀/일반 3D, 약 30명 전용 서버, 144fps 목표, 기기별 화질 조정, 쉬운 HTML/Wasm export, 품질 우선, 엔진 전용 저장소를 반영했다. C#·TS·Luau 토론을 위해 언어 선택을 재개방하고 비교 문서를 추가했다.

## 문서별 목적과 설명

[문서 지도](../README.md)의 각 행이 파일별 생성 이유와 요약이다. 생성 묶음마다 사용자에게 각 파일의 목적을 설명했다. 주요 분리는 다음과 같다.

- 헌장·원안·요구·범위표: 사용자 의도와 구현 후보·수치를 구분.
- 질문·답변: 실제 선택과 미결을 보존하고 아키텍처 영향 추적.
- 출처·주장 검증·스택·상용 엔진·조사 백로그: 사실·추정·후속 근거 분리.
- 언어 비교: C#의 CoreCLR/AOT, TS runtime, Luau와 웹 통합의 tradeoff 설명.
- 모듈별 아키텍처: 책임·소유권·입출력·실패·플랫폼·인수를 정의.
- 목표·워터폴·검증·위험: 끝낼 수 있는 일과 실제 종료 근거를 연결.
- ADR·템플릿: 결정 변경과 후속 문서의 형식을 유지.
- 루트 정책·GitHub 템플릿·검사기: 외부 기여·PR·실행 가능한 현재 체크 제공.

## Luna xhigh 작업과 검토

Superset CLI는 미로그인 상태여서 현재 대화의 하위 에이전트로 `gpt-6-luna`, `xhigh`를 호출했다. 맡긴 코드는 문서 검사기·테스트·CI이며 엔진 코드는 없다. 문서·정책·PR/이슈 양식도 해당 작업에 포함했다. 조정자는 코드·정책을 읽고 최종 검사·저장소 통합을 담당한다.

## 검증 상태

최종 로컬 검사·GitHub CI·커밋·브랜치 규칙의 실제 결과는 아래에 완료 후 기록한다. 현재 엔진 테스트는 없다. 제안된 미래 검증 명령을 실행 결과로 표시하지 않는다.

## 후속

사용자는 다음 우선순위를 스크립트 언어 결정으로 지정했다. 새 아키텍처 문서를 더 늘리는 것보다 C#·TS·Luau의 장단점·실행·reload·배포 비용을 설명하고 예측 가능한 결정을 먼저 기록한다. 미결 언어를 사용자 확정으로 오기하지 않는다.
