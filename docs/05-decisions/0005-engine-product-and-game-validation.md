# ADR-0005: 엔진 제품 인수와 3D·2D 게임 검증

날짜: 2026-10-16 · 상태: 채택 · 근거: 사용자 A-040/A-041

## 문제

기반 crate와 native live fixture의 시험은 통과했지만, AI가 외부 프로젝트를 만들어 UI·network·world·asset·physics/audio를 엮어 완성할 수 있는 엔진은 아니다. 조정자의 checkpoint 완료 보고가 사용자 전체 목표의 완료처럼 전달됐다. 또한 과거의 “현재 샘플 게임 불필요”를 이후 실게임 검증까지 금지하는 경계로 남겨두면 새로운 명시 지시와 충돌한다.

## 결정

1. 상위 목표는 `D1: AI-driven 제작용 엔진 인수 → D2: 별도 Minecraft급 3D 게임 → D3: 별도 Terraria급 2D 게임`이다. D1 인수 전에 두 게임 제작으로 건너뛰지 않는다.
2. 엔진 repository는 엔진·SDK·도구·시험만 유지한다. D2/D3는 별도 소비 프로젝트이며 엔진 소스를 고쳐야만 작동하는 fixture가 아니다.
3. 엔진 부품·fixture·PR·테스트 통과는 해당 작업의 근거다. [제품 인수표](../04-plan/product-delivery-and-acceptance.md)를 충족하기 전에는 엔진 제품이나 전체 목표를 완료 처리하지 않는다.
4. 반복되는 개발 작업 자체를 최적화한다. 공통 control/service·schema·SDK·asset dependency·재현 trace·검증/배포 자동화의 실제 중복을 줄이고 효과를 측정한다. CI cache는 이 중 한 항목이다.
5. 코딩 위임·Rust/C#/C++ 경계·기존 플랫폼/품질 목표는 유지한다. 이전 사용자 결정 없이 성능/시각/기능 기준을 임의로 낮추지 않는다.

## 기존 ADR과의 관계

ADR-0001의 엔진 전용 repository·문서 우선은 유지한다. 그 문서와 운영 지침의 “게임을 현재 시작하지 않는다”는 범위는 D1 선행 조건으로 해석하고, 게임 제작 자체를 영구 제외하는 해석은 이번 명시 지시로 대체한다. ADR-0002/0003의 실행·언어 선택은 변경하지 않는다. ADR-0004의 모듈별 구현 허용은 제품 gate 우회 권한이 아니다.

## 검증과 재검토

P01~P16의 실제 외부 제작 경로와 D2/D3의 기능·시각·행동·30명 network·저장/배포 근거를 검수한다. engine 수정이 필요한 실패는 해당 엔진 gate를 재개방한다. 공개하지 않은 game 콘텐츠 범위나 지원하지 않은 플랫폼을 임의 완료로 추가하지 않는다.
