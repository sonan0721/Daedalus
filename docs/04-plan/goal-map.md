# 완료 가능한 목표 지도

상태: 조사·설계 목표와 미래 구현 목표의 분리 · R01 · 2026-10-15

## 목표를 나누는 규칙

한 goal은 문제·입력·산출물·완료 조건·검증·미결을 갖는다. 문서가 생겼다는 이유로 설계 확정 또는 기능 구현을 완료 처리하지 않는다. 아래의 담당은 역할이며 개발 일정·소요 기간을 뜻하지 않는다. 코딩이 필요한 단계는 모두 Luna xhigh가 구현하고 조정자가 리뷰한다.

R03~R07은 조사 대상을 나눈 것이며, 코드를 여러 팀이 동시에 작성하라는 의미가 아니다. 기술 실험 코드도 자동 착수하지 않는다. 현재 사용자 요청은 명세 우선이다.

## 미래 구현 목표

아래는 로드맵이다. 코드·Cargo workspace·테스트 장면을 아직 만들지 않는다. R08 이후 사용자가 구현 단계 착수를 요청하면 해당 goal을 구체 작업으로 바꾼다.

| I02 | macOS/web 최소 presentation·입력·로딩 UI·진단 | 느린 job 중 UI·입력·표시 지연 trace, 실제 양쪽 실행 | I01 |

| I04 | asset cook/load·렌더 기본·offscreen 캡처 | 자원·색공간·재질·2D/3D fixture·비동기 readback | I02 |

I06-2D와 I06-3D는 동등한 엔진 기능 축이다. 필요하면 대화·작업 세션을 분리할 수 있지만 한쪽의 품질 요구를 삭제하지 않는다. 일반 오픈월드와 픽셀·HD 요구도 유지한다.

## 작업 단위 예시

R04의 하위 작업은 `snapshot reader 수명 정의`, `queue 종류별 포화 의미`, `pool 경쟁 예산`, `shutdown 순서`, `동시성 모델 검증 계획`처럼 나눈다. I06-2D는 `경계 transfer 보존`, `광원 제거`, `region 취소`, `네트워크 revision`처럼 독립 인수 가능한 작업으로 분해한다.

각 작업은 엔진의 어느 모듈을 바꾸는지와 어떤 요구·테스트를 충족하는지 포함한다. “엔진 완성”, “상용급”, “최적화 완료”처럼 종료 근거가 없는 작업 제목은 사용하지 않는다.
