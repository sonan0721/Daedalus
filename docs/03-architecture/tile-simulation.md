# 2D 타일·유체·라이팅 시뮬레이션

상태: 자체 설계 제안. Terraria 내부 구현을 확인했다는 뜻이 아님 · 2026-10-15

## 데이터와 소유권

2D region/chunk에 tile type·배경·충돌·유체량·유체 종류·광원·light field·dirty revision을 저장한다. 조밀 배열 또는 field별 배열을 비교하며 모든 셀을 ECS entity로 만들지 않는 안이다. 픽셀·HD 렌더 정책은 물리 cell 해상도와 분리한다.

권한 있는 CPU simulation이 gameplay 유체·지형을 소유한다. GPU는 시각적 물결·입자·왜곡을 보조할 수 있으나 화면만의 입자 결과를 저장·네트워크의 실제 유체량으로 사용하지 않는다. GPU authoritative simulation은 별도 결정성·readback 조사 없이는 채택하지 않는다.

## 유체 보존 모델

정수 또는 고정소수점 유체량과 reference solver를 기준 후보로 삼는다. `총량(next) = 총량(current) + 명시적 유입 - 명시적 유출 ± 정의된 반응`을 만족해야 한다. 최대 cell 수용량·압축성·물/용암 반응·증발·경사·하강 우선순위는 정책으로 정한다.

이중 field를 쓴다는 이유로 병렬 충돌이 사라지지는 않는다. 여러 source가 한 destination으로 보내면 용량 초과가 가능하다. 다음의 계산·확정 단계를 검토한다.

1. 고정된 이전 state와 경계 halo로 후보 이동량을 계산한다.
2. source별 총 유출·destination별 유입 capacity를 제한한다.
3. 경계 transfer를 하나의 소유 규칙과 결정적 순서로 조정한다.
4. 확정된 같은 양을 source에서 빼고 destination에 더한다.
5. 변화한 셀·인접 셀만 다음 active set에 등록한다.

구체 solver는 아직 선택하지 않았다. in-place 갱신·색칠 분할·Jacobi·edge transfer 후보의 수렴·바이어스·메모리·병렬성을 reference 결과와 비교한다. worker 순서가 달라져 총량·반응이 달라지지 않는지 확인한다.

## 영역 경계와 활성 집합

region 작업은 필요한 halo를 포함한 불변 입력을 받는다. 경계 읽기 revision과 transfer epoch를 검증하며 같은 경계 유출입을 두 번 적용하지 않는다. 잠든 region으로 들어오는 유체·새 광원·타일 편집은 wake-up 원인이 된다.

활성 셀·region·frontier·메모리·tick 처리량을 유한 예산으로 관리한다. 예산을 넘으면 남은 작업을 보존하고 age를 계측한다. simulation 속도를 임의로 줄이거나 멀리 있는 유체를 소멸시켜 통과 처리하지 않는다. 원거리·언로드 영역의 정지/근사/지속 진행은 사용자 결정이 필요하다.

## 조명과 파괴

타일 광원·차폐·재질 감쇠·색 채널·배경·햇빛 경계의 규칙을 정의한다. 광원 추가와 제거, 차폐 변경을 구분한다. 과거 light field를 남기지 않도록 제거·재전파 경로를 설계한다. 경계 전파·frontier·revision을 예산 안에서 처리한다.

타일 파괴 command는 cell state·collision query·유체·조명·render batch에 같은 의미의 변경으로 전달한다. 즉시 반영할 권한 쿼리와 지연 가능한 시각 결과를 구분한다. 유체에 잠긴 entity·호흡·피해 같은 게임 규칙을 엔진 유체 solver에 하드코딩하지 않고 이벤트·쿼리 API로 제공한다.

## 2D 표현과 액션 접점

픽셀 모드는 카메라·텍스처 필터·pixel snap·회전·확대 정책을 명시한다. HD 모드는 서브픽셀 이동·고해상도 sprite·skeletal animation·normal 기반 lighting을 다룬다. 양쪽은 같은 입력·물리·tile API를 사용하고 렌더 설정을 다르게 갖는다.

## 검증 카드

| 입력 | 정확성 조건 | 성능·응답 관측 |
| --- | --- | --- |
| 닫힌 용기·연결관 | 명시 반응 외 총량 보존·음수/용량 초과 없음 | 수렴 시간·활성 셀·queue age |
| region 경계 폭포 | 이중 적용·누락 없음 | 경계 transfer 시간·bytes |
| 대량 파괴·물/용암 | 정의된 반응·충돌·저장 정합성 | tick p99·이월량·UI 입력 지연 |
| 광원 제거·벽 설치 | 빛 잔상·경계 불일치 없음 | 수렴 지연·frontier 상한 |
| worker 수·순서 변경 | 정의된 재현 계약 만족 | 1/다중 worker 비교 |
| 30명 편집·재접속 | 권한 revision·저장·복제 일치 | 대역폭·집중 부하 |

셀 크기·지역 크기·유체 업데이트율·동시 활성량·허용 수렴 지연은 후속 질문과 실험으로 확정한다. “수천 물 블록에서도 안정적”이라는 문장만으로 인수하지 않는다.
