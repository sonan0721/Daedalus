# 엔진 기능과 품질 범위

상태: 범위 협의를 위한 설계 제안. 아래 기능은 모두 미구현 · 2026-10-15

## 왜 이 표가 필요한가

“고품질 엔진”을 PBR과 멀티스레드만으로 평가하면 캐릭터 조작, UI, 오디오, 네트워크, 저장과 배포가 빠진다. 사용자는 게임 수준의 품질을 만들 수 있는 엔진을 원한다. 따라서 엔진이 제공할 기반과 콘텐츠가 결정하는 결과를 항목별로 명확히 한다.

구체 구현 방식과 첫 릴리스 포함 범위는 후속 조사에서 정한다. 일부 항목이 장기 작업이라는 사실은 엔진의 장기 목표에서 해당 항목을 제외한다는 뜻이 아니다.

## 비주얼 참조를 엔진 계약으로 바꾸는 절차

1. 사용자가 장면 또는 기능을 고른다. 게임명만으로 렌더 요구를 확정하지 않는다.
2. 색, 재질, 그림자, 실루엣, 캐릭터, VFX, UI·카메라 등 비교 항목을 분리한다.
3. 엔진 기능, 에셋 품질, 아트 설정의 책임을 기록한다.
4. macOS·웹에서 같은 의미를 갖는 기능과 장치별 비용을 정한다.
5. 이미지와 움직임·조작의 검증 기준을 함께 만든다. 스크린샷 하나를 전체 품질 증거로 사용하지 않는다.

## 품질 계약 카드

각 영역은 `기능 ID / 사용자 시나리오 / 기준 플랫폼·기기 / 입력 규모 / 정확성 조건 / 지연·메모리 상한 / 시각 또는 체감 기준 / 증거 / 미결`을 갖는다. 현재 기기와 수치가 없어 품질 카드의 완성을 선언하지 않는다.

후속 문서: 재질·조명 참조 분석, 캐릭터·액션 계약, UI·접근성 명세, 오디오 명세, 에셋 포맷 및 쿠킹 명세. 이 문서들을 별도 조사 목표로 추적한다.
